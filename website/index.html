Privacy that's actually privatePrivacy & Security Architecture

Most "private" health apps mean "we encrypt it before we sell it." We mean: your data lives on your device, full stop. No cloud. No account. No login server. The app doesn't even know you exist.Chaos Command is a fully local-first application. There is no cloud sync, no account system, and no server-side data layer. The application runs as a Tauri desktop binary or Android APK with on-device storage only.

What this means in practiceArchitectural Properties

  • No cloud, ever.No network egress for core functionality. Your symptoms never touch a server. Not ours, not anyone's.All tracker data, parsed documents, and reports are stored in local IndexedDB.
  • No account.No identity layer. Nothing to sign up for. Nothing to log into. Nothing for a breach to leak.The application has no authentication endpoint, user record, or telemetry pipeline.
  • Update checks are opt-in.Update polling is opt-in. Off by default. You decide if and when the app asks GitHub if there's a new version. Otherwise: silent.No background polling. The user must explicitly invoke the update-check action.
  • PIN-protected danger zone.PIN-gated destructive operations. Anything that could wipe your data makes you re-type your PIN first — so it can't happen by accident, even by you, and you can't delete the wrong person's profile by mistake.Destructive operations require re-entry of the active PIN before execution, preventing accidental or wrong-profile deletion.
  • HIPAA-irrelevant by design.HIPAA scope avoidance. There is no covered-entity transmission to regulate. No data leaves the device.No data leaves the device, so no transmission is in scope for protection regulation.

The "things go sideways" featuresAdversarial-Scenario Tools

  • One-tap Logout.One-tap session lock. Big button at the bottom of the sidebar. Tap it and you're instantly back to the locked PIN screen — your data's still there and safe, but no one's getting in without your PIN. Fast exit, nothing to fumble for.Prominent sidebar action returns the app to the locked PIN screen immediately; no session state remains exposed and data stays behind the PIN.
  • Honest encrypted backups.AES-256-GCM encrypted export. Export everything as a real password-protected file. It's the default — plain unencrypted export still exists, but it's tucked behind an "Advanced" toggle so you only ever do it on purpose. No disguises, no tricks: the protection is strong, honest encryption you control.Password-derived AES-256-GCM (PBKDF2, 210k iterations) is the default export path; plain JSON export is gated behind an explicit "Advanced" disclosure. Security comes from the cryptography, not obscurity — no steganographic layer.
  • QR Sync (no server).QR-based local transfer. Move data device-to-device by reading a QR code. Nothing in the middle. No relay.Device-to-device data transfer via QR code without any intermediate server.
  • Permanent delete — only yours.Per-profile permanent deletion. Wipe your profile's data for good from Settings — no undo, no kept copy. It makes you re-type your PIN first, so you can never delete the wrong person's profile by accident, and other PINs on the same device are never touched.Deletes only the logged-in PIN's local database after re-entry of the active PIN; other profiles on the device are unaffected. No recovery path, no backup retention.
Why we built it this way: people in domestic-violence situations, immigration-precarious situations, people whose conditions are stigmatized at work or church or with family — medical tracking can't be a liability. So we made it not one: a one-tap exit, real encryption you control, and a delete that's actually a delete.Design rationale: users in high-risk personal contexts (intimate-partner violence, immigration precarity, employment or social stigma) cannot use applications that assume a benign threat model. Local-first storage, one-tap session lock, user-controlled AES-256 encryption, and verified per-profile deletion address this without relying on fragile disguise.

Seventeen decisions, one flowRoutines & Guided Flows

On a bad day — the kind where executive function has packed its bags and left — opening seventeen separate trackers one at a time is exactly the friction that makes you give up and log nothing. And then you have a gap in your data on the days that matter most. Routines fix that: build a named set of trackers once, run the whole thing in a single guided flow.Routines let the user define a named set of tracker modules and complete them as one sequential flow rather than navigating to each module individually, reducing the interaction cost that causes logging gaps on high-symptom days.

How it worksFlow Mechanics

  • Build once, run whenever.Reusable named sets. A morning check. A meal-and-meds pass. A hydration nudge you run five times a day. Make it once, run it any time.Each routine is a saved, reusable ordered set of tracker modules; invocation is unrestricted.
  • Each run starts fresh.Run-scoped, not day-locked. A routine is scoped to the moment you tap Run — not locked to once a day. Run your hydration routine as many times as you actually drink.Flow state is scoped per invocation rather than per calendar day, supporting multiple same-day runs.
  • The flow bar carries you.Sequential flow bar. A bar at the bottom chains you tracker to tracker. You're not navigating — you're just moving forward. A checkmark lands when you're done.A persistent flow bar advances through the set tracker-to-tracker with completion indication.

The small things that matterLow-Friction Affordances

  • "Copy last."Copy-previous entry. If today looks like yesterday, one tap clones your most recent entry. Done. Move on.One-tap duplication of the most recent entry for a module.
  • "Nothing today" is real data.Explicit null logging. If a tracker just didn't happen today, that's not skipping — it's logging that nothing happened. Your doctor needs to know you had a week without seizures as much as a week with one."Nothing today" records an affirmative null, distinguishing a true negative from missing data — clinically meaningful for symptom-free intervals.
  • Custom trackers join too.Forge integration. Trackers you built in the Forge drop into routines right alongside the built-in ones.User-built (Forge) trackers are first-class members of routine sets.
Why it might be the feature that makes you actually use this: the hardest part of tracking isn't any one entry — it's the friction of starting, every single day, when you feel worst. Routines turn seventeen decisions into one. If the app is easy to open on a bad day, you log. If you log, you have data. If you have data, your doctor listens.Design rationale: adherence on high-symptom days is the binding constraint for longitudinal self-tracking. Collapsing per-module interaction cost into a single guided flow directly targets that constraint.
